# Project Evaluation
## Post-Development Reflection

Overall, I believe my completed text-RPG performed very well against the original success criteria. I was able to turn the original idea into a fully developed RPG with a creative story, multiple locations, NPCs, different enemies and bosses, weapons, inventory, dialogue and a complete combat system. This made the final product much more developed than the basic concept I started with.

One of the strongest parts of my game is the amount of content and variety included. Different enemies have different health and attack values, while bosses provide more difficult encounters for the player. I also included different weapons with different damage values and rarities, which gives the player more reasons to explore and collect items. The dialogue system also adds more depth to the world because NPCs can have different conversations and choices.

The game successfully runs in an application window and uses a clear interface with menus, health bars, combat information and formatted text. I focused on making the game easy to understand while still giving it its own visual style. The different locations and descriptions also help make the game feel like an actual world rather than just a collection of menus.

I think I also performed well with the code structure. I used object-oriented programming throughout the project, creating classes for characters, enemies, weapons, areas, dialogue, inventory and other game systems. This kept the project organised and made it easier to add new content without rewriting the entire program. For example, creating a new enemy can be done using the existing `Enemy` class rather than creating completely new code for every enemy.

During testing and development, I found that some sections could still be improved. The combat system contains some repeated code for displaying health bars and combat prompts, which could be moved into reusable functions to improve efficiency. There were also some integration issues between systems that needed to be checked carefully, particularly when combining combat, inventory and area travel. However, identifying these issues during testing helped me improve the reliability of the final game.

In terms of optimisation, the game does not use unnecessarily complicated algorithms or large amounts of data, so performance was generally good. The main improvements I would make would be reducing repeated code and making some functions more reusable. This would make the program easier to maintain and allow future features to be added more efficiently.

Overall, I am very happy with the final result. I believe I successfully met the original quality criteria and went beyond the basic requirements by creating a game with a large amount of content and multiple interconnected systems. The project also helped me improve my understanding of object-oriented programming, debugging, testing and designing a larger program. While there are still small areas that could be optimised, the final game is functional, organised and much more complete than my initial concept.
